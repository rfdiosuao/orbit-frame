# 稳定性与恢复

生成前先检查网关、豆包客户端调试连接、聊天页、本地登录状态和桥接接口。首页会显示故障原因与“重新检查连接”；本地密钥仍自动配置，无需手动输入。连接检查不生成视频，也不能证明额度或服务端生成权限有效。

## 不重复生成

- 尚未提交：API 返回 `error.submitted: false`，不创建视频任务，首页允许修改提示词后重试。
- 提交结果不明：保留原幂等键和任务；不会自动重新发出生成请求。请先在豆包核对。
- 生成中断线：保留原会话与运行编号。读取失败按退避间隔重试，连续三次后显示待恢复状态；连接恢复后可继续跟踪。
- 确认结果不明：确认操作在发出前记录，每个确认只尝试一次。需要核对客户端，避免重复点击。
- 下载或校验失败：使用“重新提取视频”重试原任务，不重新生成。
- 监控超过一小时：暂停后台查询。手动“继续查询原任务”可以续接监控。
- 无会话编号的旧异常任务：在客户端核对后，可结束本页跟踪。此操作保留作品库记录，不取消豆包生成。

后台状态读取使用共享连接与超时保护；提取队列最多并发两个任务，下载不会阻塞其他任务的状态读取。普通状态查询只读取本地记录；网页通过一条 SSE 接收变化，失效后再以轮询恢复。

后台读取会短时续接原任务的实时消息流（1500 毫秒窗口），补齐尚未写入历史的确认与视频卡片。它使用已接受的会话和运行编号续接，完成的任务直接复用历史快照。不能只删掉实时续接步骤，否则部分任务会停留在空历史的“生成中”。

页面查询遇到短暂网关中断，会以退避间隔自动重连原任务，最多六次；失败后保留任务编号并提供手动查询。多进程共享任务时，SSE 心跳也会检查本地文件更新，防止预览遗漏另一个进程写入的完成状态。

共用任务目录的网关只有一个后台监控进程持有所有权，其他网关可以读取状态但不会重复推进。原监控进程退出后自动接管。升级时应停止仍在运行的旧版实例，旧版本不认识此保护机制。

## CLI / Agent

```sh
npm run video:desktop -- check
npm run video:desktop -- generate "清晨湖面上的纸船，慢镜头" --duration 5 --ratio 16:9 --output data/exports/boat.mp4
npm run video:desktop -- generate --task TASK_ID --output data/exports/boat.mp4
npm run video:desktop -- status TASK_ID --refresh
```

`generate` 提交一次、等待并保存 MP4。输出文件已存在时拒绝覆盖。短暂断线会重试只读请求；提交响应丢失时返回 `error.task_id` 和 `query_same_task`，Agent 应查询该任务，不要重复提交。若任务查询暂时返回不存在，稍后再查并在豆包核对；这不证明此前未提交。

MCP 工具 `check_video_connection` 用于连接检查，`generate_and_wait` 支持三种生成模式；`get_video_status` 的 `refresh: true` 用于续接或重试提取。错误通过结构化 `error.code`、`submitted`、`next_action` 返回，密钥不进入工具输出。

API：`GET /v1/videos/readiness`、`GET /v1/videos/tasks/:id`、`GET /v1/videos/tasks/:id?refresh=1` 和 `GET /v1/videos/tasks/:id/events` 都需要 Bearer 鉴权。任务响应提供 `last_checked_at` 和 `timings_ms`，方便区分提交、客户端读取与下载耗时。

## 验证边界

`npm test` 包含断线、读取超时、重启遗留任务、确认去重、提取队列、响应丢失与 CLI/MCP 恢复测试。模拟测试不能替代实际生成、MP4 校验和浏览器播放验收。

系统仍依赖豆包桌面客户端的内部接口；退出客户端、登录失效、上游排队和客户端升级仍可能影响生成。本次改动保证尽量保留状态、给出原因并提供恢复路径，无法消除上游故障。
